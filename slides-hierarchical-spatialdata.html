Hierarchical
SpatialData

grouping elements under a common namespace
Luca Marconato · EMBL · branch: vibecoded-experiment/hierarchical-spatialdata

The Problem

A flat namespace — all elements live at the same level.

SpatialData object ├── sample1_he_image [Image2D] DataArray[cyx] (3, 4096, 4096) ├── sample1_dapi_image [Image2D] DataArray[cyx] (3, 4096, 4096) ├── sample1_cells [Shapes] GeoDataFrame (12043, 2) ├── sample1_nuclei [Labels2D] DataArray[yx] (4096, 4096) ├── sample2_he_image [Image2D] DataArray[cyx] (3, 4096, 4096) ├── sample2_dapi_image [Image2D] DataArray[cyx] (3, 4096, 4096) ├── sample2_cells [Shapes] GeoDataFrame (9871, 2) └── sample2_nuclei [Labels2D] DataArray[yx] (4096, 4096)
no grouping semantics
name collisions across samples
long repetitive names

The Solution

Use "/" as a path separator — like a filesystem.

SpatialData object ├── sample1/ (4 elements) │ ├── he_image [Image2D] DataArray[cyx] (3, 4096, 4096) │ ├── dapi_image [Image2D] DataArray[cyx] (3, 4096, 4096) │ ├── cells [Shapes] GeoDataFrame (12043, 2) │ └── nuclei [Labels2D] DataArray[yx] (4096, 4096) └── sample2/ (4 elements) ├── he_image [Image2D] DataArray[cyx] (3, 4096, 4096) ├── dapi_image [Image2D] DataArray[cyx] (3, 4096, 4096) ├── cells [Shapes] GeoDataFrame (9871, 2) └── nuclei [Labels2D] DataArray[yx] (4096, 4096)
natural grouping
short names within a group
slice by prefix

API

before
SpatialData(
  images={
    "s1_he":   img1,
    "s1_dapi": img2,
    "s2_he":   img3,
  },
  labels={
    "s1_nuclei": lbl1,
    "s2_nuclei": lbl2,
  },
)
after
SpatialData(
  elements={
    "sample1/he":     img1,
    "sample1/dapi":   img2,
    "sample1/nuclei": lbl1,
    "sample2/he":     img3,
    "sample2/nuclei": lbl2,
  },
)
Old images=, labels=, … kwargs still work — they merge into the flat elements dict.

Mock code — before

# ── create ──────────────────────────────────────────────────────
sdata = SpatialData(
    images = {"sample1_he": he1, "sample2_he": he2},
    labels = {"sample1_nuclei": lbl1, "sample2_nuclei": lbl2},
    tables = {"sample1_table": tbl1, "sample2_table": tbl2},
)

# ── access ──────────────────────────────────────────────────────
sdata["sample1_he"]           # → DataArray  (searches all typed containers)
sdata.images["sample1_he"]   # → DataArray  (via typed container)
sdata.images                    # → Images container with ALL images flat

# ── on-disk layout ──────────────────────────────────────────────
sdata.write("study.zarr")
# study.zarr/images/sample1_he/    ← type subdir required
# study.zarr/labels/sample1_nuclei/
# study.zarr/tables/sample1_table/

# ── partial read — must know the type subdir ────────────────────
read_zarr("study.zarr", selection=["images"])

Mock code — after

# ── create ──────────────────────────────────────────────────────
sdata = SpatialData(elements={
    "sample1/he":      he1,   "sample2/he":      he2,
    "sample1/nuclei":  lbl1,  "sample2/nuclei":  lbl2,
    "sample1/table":   tbl1,  "sample2/table":   tbl2,
})

# ── access ──────────────────────────────────────────────────────
sdata["sample1/he"]   # → DataArray  (direct dict lookup)
sdata["sample1"]      # → SpatialData  keys: {"he", "nuclei", "table"}
sub = sdata["sample1"]
sub["he"]            # → DataArray  (same as sdata["sample1/he"])
sdata.images        # → dict  {"sample1/he": …, "sample2/he": …}

# ── on-disk layout ──────────────────────────────────────────────
sdata.write("study.zarr")
# study.zarr/sample1/he/      .zattrs → {element_type: "images"}
# study.zarr/sample1/nuclei/  .zattrs → {element_type: "labels"}
# study.zarr/sample2/he/      .zattrs → {element_type: "images"}

# ── partial read — just point at a subfolder ────────────────────
sub = SpatialData.read("study.zarr/sample1")  # keys: {"he", "nuclei", "table"}

What changed

  • Single _elements: dict[str, SpatialElement | AnnData] replaces five typed containers
  • "/" allowed in element names — each path component validated independently
  • sdata["sample1"] returns a sub-SpatialData view with stripped prefix keys
  • Typed properties (.images, .labels, …) now return filtered plain dicts
  • Tree-style repr groups elements under their common prefix folder

repr

SpatialData object ├── global_points: [Points2D] DataFrame (1000, 3) └── sample1/ (3 elements) ├── he: [Image2D] DataArray[cyx] (3, 4096, 4096) ├── labels: [Labels2D] DataArray[yx] (4096, 4096) └── table: [Table] AnnData (12043, 500) with coordinate systems: ▸ 'global', with elements: global_points, sample1/he, sample1/labels
Flat elements (no /) render at root level.
Grouped elements collapse under a folder/ header.

Backwards compatible

# ✓  old-style kwargs still work
sdata = SpatialData(images={"img": img}, labels={"lbl": lbl})

# ✓  typed property access still works
sdata.images   # → dict[str, Raster_T]  (filtered from _elements)
sdata.labels   # → dict[str, Raster_T]
sdata.tables   # → dict[str, AnnData]

# ✓  setitem / delitem still work
sdata["img"] = img2
del sdata["img"]

# ✓  new: prefix delete
del sdata["sample1"]  # removes all sample1/* elements

# ✓  new: prefix slice
sub = sdata["sample1"]  # SpatialData with keys {"he": …, "labels": …}

I/O — flat Zarr layout

old layout (v0.1 / v0.2)
store.zarr/ ├── images/ │ ├── sample1_he/ │ └── sample1_dapi/ ├── labels/ │ └── sample1_nuclei/ └── tables/ └── sample1_table/
new layout (v0.3)
store.zarr/ └── sample1/ ├── he/ │ └── .zattrs → {element_type: "images"} ├── dapi/ │ └── .zattrs → {element_type: "images"} └── nuclei/ └── .zattrs → {element_type: "labels"}
Reader scans recursively for spatialdata_attrs.element_type to identify elements. v0.1 / v0.2 stores are read with the old path — backward compat preserved.
